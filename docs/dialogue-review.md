# 日本語台本のレビューガイド

## 台本の種類を決める

| 種類 | 書く内容 | 画面での表示 | 実装 |
| --- | --- | --- | --- |
| 台詞 | その場にいる話者が相手に言う言葉 | 話者名、顔絵、かぎ括弧 | `Beat::speech`、`Message::spoken` |
| 状況 | プレイヤーが見たこと、行動、会話の結果 | 「状況」の見出しと本文 | `Beat::scene`、`Message::narration`。分岐結果もこの形式 |
| 記録 | 帳面、札、手紙、石碑に残った声の内容 | 資料や声の出所と本文 | `Beat::record`、`Message::record` |
| 案内 | 操作や次の行動をプレイヤーに伝える情報 | 「案内」の見出しと本文 | `Message::guide` |

台詞は話者名と顔絵を場面ごとに指定する。同じ人物が別の場所で話しても名前と顔絵は揃える。「村人」のような一括名は、固有名がなくても「小屋の世話役」「水路の当番」まで絞れるか確認する。姿を見せない声や対応する顔絵がない人物には、話者名だけで表示する `Beat::voice` を使える。台詞全体のかぎ括弧は描画側が付ける。台詞の中で引用するときは『』を使う。

## 一文ずつ確認する

1. **誰が誰に言うか。** 相手との関係や口調を先に決める。名前を呼ぶ、敬語にする、語尾を砕くなどは関係に合わせる。同じ人物を続けて読み、急に別人の口調になっていないか確かめる。
2. **今、なぜ言うか。** 見た物、困ったこと、相手に頼むことの順に書けるか確かめる。両者が知っている事情は、知らない相手に説明するように言い直さない。相手が次に向かう場所が判断できるだけの具体性を残す。
3. **声に出して読む。** 主語と相手が分かるときは繰り返さない。「出港印の主」などの固いまとめ言葉は、場面に即した動詞に戻す。「誰が船を出したか」のように、ひと息で言える言葉を選ぶ。
4. **一画面に一種類。** 話者の発言に、観察したことやボタンの説明が混ざっていないか確認する。会話の直後に調査結果を見せる場合も、必要なら画面を分ける。地の文は視点と時制を揃え、誰の行動か迷う場合は名前や役割を補う。
5. **選択肢と結果を照合する。** 直前の台詞を読んで、二つの選択肢がどちらも理解できるか確かめる。分岐後は、誰が何をして、何が変わったかを具体的に描く。

## 修正例

- 水門で魔物が出る場面は、アレンの顔絵の横に地の文と操作説明が出ていた。剣を差し込み、リリスが門を支える場面を「状況」で描き、戦い方は戦闘画面で伝える。
- 「炉の名札」で夜番が働いていたことを第三者の文で説明していた。「名札のない薪束にも、私の刻み目があるでしょう。夜番をしてることなら話していいよ。」と本人に言わせる。分岐後は顔絵を外し、薪札や配給帳の行方を描く。
- オオ麦の里の積み荷控えでは、書き手の指示をそのまま載せる。控えを見た人物に、書いてあることを口頭で説明させる必要があるかを先に考える。

## ゲーム内で確認する

- デバッグモードから該当のイベントを開き、直前と直後を含めて読む。会話は本文を読む前に話者が分かり、調査・記録・結果は顔絵や発話のかぎ括弧が出ていないことを確認する。
- 320×240の論理解像度で、選択肢のある本文は話者名を除いて6行以内を目安にする。句読点や閉じ括弧が行頭に来ないか、本文が選択肢や決定表示と重ならないかを画面で見る。スマホ横画面では十字キー・決定ボタンとの重なりも確認する。
- 主な確認先は、序章の炉番・水門・石碑、ノクスのサイドストーリー「炉の名札」「父の手袋」「種蔵の秤」。口調と視点は音読、画面の種別と進行はテストでも確認する。
